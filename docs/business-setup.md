# ตั้งค่ากิจการครั้งแรก

ชุดติดตั้ง `business` ที่ยังไม่มีเจ้าของจะเปิด `/setup` อัตโนมัติ โดยไม่ต้องผ่านหน้าล็อกอิน เริ่มจากสร้างชื่อเจ้าของ ชื่อผู้ใช้ และ PIN ตัวเลข 4–6 หลัก เมื่อสร้างสำเร็จระบบเข้าสู่บัญชีเจ้าของให้และพาไปตั้งค่ากิจการต่อ

ระบบตรวจสถานะจากเซิร์ฟเวอร์ การติดตั้ง Desktop หรือเปิดเบราว์เซอร์ใหม่ที่เชื่อมกิจการเดิมยังต้องเข้าสู่ระบบตามปกติ ไม่ใช้การไม่มีข้อมูลในเครื่องเป็นหลักฐานว่ากิจการยังไม่มีเจ้าของ หากติดต่อเซิร์ฟเวอร์ไม่ได้จะแสดงปุ่มลองใหม่ ไม่เปิดการสร้างเจ้าของจากข้อมูลออฟไลน์

หลังสร้างเจ้าของแล้ว ผู้ดูแลเปิด **หลังบ้านกิจการ → เริ่มต้นใช้งานกิจการ** หรือ `/setup` กลับมาทำต่อได้ หน้าแดชบอร์ดแสดงปุ่มเริ่มตั้งค่าหรือทำต่อจนกว่าจะยืนยันครบ บัญชี manager/cashier และชุดติดตั้ง `platform` ไม่มีสิทธิ์เข้า API ตั้งค่ากิจการ

## เตรียมการติดตั้งใหม่

ก่อนสร้างเจ้าของ ระบบตรวจการเชื่อมต่อฐานข้อมูล ตารางข้อมูล การออก session และระบบบัญชี ถ้ายังไม่พร้อมจะเปิดหน้าตรวจความพร้อมและปุ่มตรวจอีกครั้ง ผู้ติดตั้งเตรียมค่าจาก [ตัวช่วยติดตั้งระบบ](./system-installation.md) ซึ่งเลือกได้ทั้ง Supabase และ PostgreSQL ในเครื่อง

Production ต้องตั้ง `PUMPPOS_INSTALLATION_CODE` เป็นรหัสสุ่มส่วนตัวอย่างน้อย 32 ตัวอักษร พร้อม `APP_SECRET` อย่างน้อย 32 ตัวอักษร และค่าการเชื่อมต่อ Supabase Auth ฝั่งเซิร์ฟเวอร์/เว็บให้ตรงกัน ผู้ติดตั้งส่งลิงก์ `https://pos.example.com/setup#install=<รหัสติดตั้ง>` ให้เจ้าของ หรือให้กรอกรหัสในฟอร์ม ห้ามใส่รหัสใน `VITE_*` หรือ Git

เว็บอ่านรหัสจาก fragment แล้วลบออกจาก URL และเก็บเฉพาะในหน่วยความจำของฟอร์ม ชื่อผู้ใช้และ PIN ที่เจ้าของกำหนดใช้กับระบบเข้าสู่ระบบเดิม Production ต้องยินยอมและลงทะเบียนใบหน้าก่อนสร้างบัญชี จึงเข้าสู่ระบบครั้งต่อไปได้ด้วย PIN และใบหน้า โดยใช้ Supabase session จริง โหมดพัฒนาไม่บังคับใบหน้าและไม่บังคับรหัสติดตั้งหากไม่ได้กำหนดไว้

สร้างเจ้าของได้เฉพาะฐานใหม่ที่ไม่มีบัญชีหรือข้อมูลการดำเนินงาน หรือ seed รุ่นนี้ที่มีสถานะรอเจ้าของอย่างชัดเจนเท่านั้น บัญชีเดิม แม้ถูกปิดใช้งานหรือยังตั้งค่าไม่ครบ ไม่เปิดสิทธิ์สร้างเจ้าของใหม่ API bootstrap รุ่นเก่าที่ปิดไว้ยังตอบ 410 ตามเดิม

การสร้างเจ้าของพร้อมกันจากหลายเครื่องถูกตรวจใน transaction บัญชีแรกได้รับสิทธิ์ผู้ดูแลทั้งหมดและผูกกับสาขาหลัก หากไม่ได้รับผลตอบกลับให้ลองใหม่จากฟอร์มเดิม คำขอเดิมและข้อมูลเดิมลองรับ session ซ้ำได้ในช่วง 10 นาที หลังจากนั้นใช้ชื่อผู้ใช้และ PIN ที่สร้างไว้เข้าสู่ระบบตามปกติ PIN รหัสติดตั้ง และข้อมูลใบหน้าไม่ถูกบันทึกใน localStorage หรือคิวขายออฟไลน์

## ขั้นตอน

1. **ข้อมูลกิจการและสาขา** — ชื่อกิจการ ชื่อสาขา ที่อยู่ โทรศัพท์ และเลขภาษี นำไปใช้ในใบเสร็จ บันทึกเฉพาะสาขาที่กำลังใช้งาน
2. **สินค้าและหัวจ่าย** — ตรวจและแก้สินค้าที่มีอยู่ ราคาขาย ต้นทุน จำนวนสินค้า ถัง และเลขมิเตอร์ รวมถึงเพิ่มสินค้าและชุดถัง–ตู้–หัวจ่ายได้ในหน้านี้ ใช้ความจุ ระดับน้ำมัน และเลขลิตรสะสม L/เลขเงินสะสม P จากอุปกรณ์จริง
3. **ผู้ใช้งาน** — เจ้าของใช้บัญชีปัจจุบันเริ่มขายได้ หรือเพิ่มพนักงานในสาขานี้ เลือกพนักงานขายหรือผู้จัดการ บัญชีใหม่ที่ยังต้องลงทะเบียนใบหน้าจะแสดงสถานะรอ พร้อมขั้นตอนยินยอมและลงทะเบียนใบหน้า
4. **การรับเงิน** — เลือกช่องทางที่ใช้จริง ถ้าเปิด QR ระบบตรวจว่ามีผู้รับเงินที่สร้าง QR ได้ พร้อมเพย์กรอกเพิ่มได้ ส่วน QR ร้านค้าถุงเงินและบริการตรวจสลิปจัดการได้ในหน้าตั้งค่าเดิม
5. **การพิมพ์และค่าระบบ** — เลือกกระดาษใบเสร็จ 58/80 มม. ใบกำกับภาษี A4/A5 การพิมพ์อัตโนมัติ อัตราภาษี และแต้มสมาชิก พร้อมทางเข้าตั้งค่าโลโก้ ธีม โปรโมชั่น สำรองข้อมูล AI และบริการรับเงินที่เลือกใช้
6. **ตรวจความพร้อม** — แสดงสิ่งที่ยังขาดและปุ่มกลับไปแก้ เมื่อบันทึกและยืนยันครบจึงกดจบและไปเปิดกะ ระบบไม่เปิดกะหรือสร้างบิลให้เอง

บันทึกทีละขั้นและกลับมาทำต่อจากอุปกรณ์อื่นได้ผ่านบัญชีและสาขาเดิม การออกจากหน้าก่อนบันทึกไม่ถือว่าสำเร็จ PIN ของพนักงานที่กำลังเพิ่มเก็บเฉพาะในฟอร์มและล้างหลังสร้างสำเร็จ ไม่บันทึกไว้ในความคืบหน้า

## ข้อมูลเดิมและการบันทึก

การมีชื่อร้าน สินค้า ถัง หรือหัวจ่ายจากค่าตั้งต้น **ไม่ถือว่าตั้งค่าเสร็จ** เจ้าของต้องตรวจและยืนยันข้อมูลจริง การตั้งค่านี้ไม่ล้างข้อมูลเดิม ไม่เปลี่ยนตัวนับเลขเอกสาร โปรโมชั่น โลโก้ ธีม AI หรือค่าบริการตรวจสลิปที่ฟอร์มไม่ได้แก้

ข้อมูลกิจการและช่องทางรับเงินบันทึกผ่าน API ที่จำกัดฟิลด์และทำ transaction การแก้ผู้รับพร้อมเพย์ไม่เขียนทับ merchant mode, secret หรือ webhook token ของการรับเงินเดิม การแก้สินค้าใช้ PATCH เฉพาะค่าที่เปลี่ยน

การเพิ่มชุดถัง–ตู้–หัวจ่ายทำใน transaction เดียวและเก็บ request ID เพื่อรองรับการลองใหม่เมื่อไม่ได้รับผลตอบกลับ การแก้อุปกรณ์เดิมบันทึกเฉพาะค่าที่เปลี่ยนและตรวจข้อมูลถังหลังแก้ ต้องปิดกะก่อนเพิ่มหรือแก้อุปกรณ์ การแก้ถังที่หลายหัวจ่ายใช้ร่วมกันมีผลกับทุกหัวจ่ายในถังนั้น ข้อมูลความคืบหน้าและการทำรายการซ้ำเก็บใน `pos.settings` ของสาขาเดิม จึงไม่ต้องเพิ่ม schema หรือ migration

คำขอบันทึกจากหน้านี้ระบุสาขาที่ฟอร์มโหลดไว้ เซิร์ฟเวอร์เทียบกับสาขาปัจจุบันและปฏิเสธหากไม่ตรงกัน เพื่อป้องกันการนำฟอร์มเก่าไปบันทึกอีกสาขาหลังสลับสาขา

API ตรวจข้อมูลล่าสุดก่อนยืนยันและก่อนจบ เช่น สินค้าที่ขายได้ หัวจ่ายที่ผูกกับสินค้าน้ำมันและถังชนิดเดียวกัน และช่องทางรับเงินอย่างน้อยหนึ่งทาง ถังที่ยังไม่มีน้ำมันหรือพนักงานที่รอลงทะเบียนใบหน้าแสดงเป็นข้อควรเตรียมเพิ่มเติม การจบหน้าตั้งค่าไม่ได้ทดแทนการตรวจอุปกรณ์จริงหรือการทดสอบขาย–ปิดกะ

## การติดตั้งและทดสอบ

อัปเดต frontend, Node/Edge backend และ Desktop รุ่นเดียวกัน ขั้นตอนนี้ใช้ permission key `setup` และข้อมูล settings ที่มีอยู่ ไม่ต้องรัน migration ใหม่ ผู้ดูแลได้รับสิทธิ์ทั้งหมดตามกติกาเดิม ตัวตรวจ API ตั้งค่ากิจการใช้ permission `setup` จากทะเบียนกลางและขอบเขต `business` จากเซิร์ฟเวอร์ การตรวจสถานะและสร้างเจ้าของก่อนมีบัญชีเป็น API เฉพาะที่ตรวจฐานใหม่และรหัสติดตั้งฝั่งเซิร์ฟเวอร์ ไม่ได้เปิด API ตั้งค่ากิจการอื่นให้ผู้ไม่เข้าสู่ระบบ

การสร้างพนักงาน production ใช้ระบบ Supabase Auth เดิม และการเข้าใช้ PIN ต้องผ่านกติกาใบหน้า/passkey เดิม ไม่มีการสร้างรหัสผ่านตัวอย่างหรือข้ามการตรวจยืนยันตัวตน
