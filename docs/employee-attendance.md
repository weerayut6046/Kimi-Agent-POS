# ระบบลงเวลาเข้า–ออกงานพนักงาน

ระบบลงเวลาใช้ QR ประจำสาขาเพื่อเปิดคำทดสอบใบหน้าแบบใช้ครั้งเดียว จากนั้นตรวจใบหน้าและความเป็นบุคคลจริงบนสมาร์ทโฟนก่อนเชื่อมรายการลงเวลาเข้ากับกะที่จัดไว้ให้อัตโนมัติ ไม่มีการลงเวลาด้วย QR เพียงอย่างเดียว

## การติดตั้ง

1. ตั้งค่า `APP_SECRET` ฝั่งเซิร์ฟเวอร์ให้เป็นค่าสุ่มยาวอย่างน้อย 32 ตัวอักษร ห้ามใช้ตัวแปรที่ขึ้นต้นด้วย `VITE_`
2. ติดตั้ง migration ตามสภาพแวดล้อม (รวมตาราง `employee_face_profiles`)
   - PostgreSQL ปกติ: `npm run db:migrate`
   - Supabase: deploy migrations ใน `supabase/migrations` ตามกระบวนการของโครงการ
3. เปิด `/attendance` สำหรับพนักงาน หรือเลือกเมนู **ลงเวลาเข้า–ออกงาน**
4. ผู้ดูแลระบบหรือผู้จัดการเปิด `/attendance/kiosk` บนจอประจำสาขาเพื่อแสดง QR
5. ผู้ดูแลระบบหรือผู้จัดการเปิด `/attendance/enroll` เพื่อลงทะเบียนใบหน้าพนักงานก่อนใช้งานครั้งแรก

## ขั้นตอนใช้งาน

1. พนักงานเข้าสู่ระบบบนสมาร์ทโฟนและเปิดหน้าลงเวลา
2. สแกน QR จากจอสาขาด้วยกล้องในหน้าเว็บ หรือกล้องปกติของโทรศัพท์
3. ระบบตรวจ QR แล้วออกคำสั่งสุ่มให้กะพริบตาหรือหันหน้า จากนั้นตรวจ Anti-spoof, Liveness และเปรียบเทียบ Face Embedding กับข้อมูลที่ลงทะเบียน
4. ระบบบันทึก **เข้างาน** หรือ **ออกงาน** เมื่อใบหน้าผ่านเกณฑ์เท่านั้น
5. เมื่อเข้างาน ระบบค้นหากะของพนักงานในช่วง 2 ชั่วโมงก่อนเริ่มกะถึง 4 ชั่วโมงหลังสิ้นสุดกะ แล้วผูกกะและคำนวณเวลาสายให้อัตโนมัติ
6. เมื่อออกงาน ระบบคำนวณเวลาทำงาน เวลากลับก่อน และเปลี่ยนสถานะกะเป็นเสร็จสิ้น

หากไม่พบกะที่ตรงกัน ระบบยังบันทึกเวลาได้ แต่กำหนดสถานะเป็น `pending` เพื่อให้ผู้ดูแลตรวจสอบภายหลัง

## การป้องกันการบันทึกซ้ำและการส่งต่อ QR

- QR ลงนามด้วย HMAC และหมดอายุภายใน 45 วินาที จอ kiosk สร้าง QR ใหม่ทุก 30 วินาที
- QR ใช้ได้เฉพาะพนักงานของสาขาที่สร้าง QR นั้น และออก Face Challenge ที่ผูกกับบัญชีพนักงาน
- Face Challenge หมดอายุภายใน 3 นาทีและผูกคำสั่ง Liveness กับการเข้า/ออกงานฝั่งเซิร์ฟเวอร์
- คำขอเดิมส่งซ้ำได้อย่างปลอดภัยด้วย idempotency key
- พนักงานหนึ่งคนมีรายการเข้างานที่ยังไม่ปิดได้เพียงรายการเดียว
- ตารางลงเวลาไม่เปิดให้ `anon` หรือ `authenticated` อ่านหรือเขียนตรงจาก Data API การใช้งานทั้งหมดต้องผ่าน API ของแอป

QR แบบหมุนช่วยลดความเสี่ยงจากภาพเก่า แต่ยังไม่สามารถยืนยันตำแหน่งทางกายภาพได้ทั้งหมด หากต้องการการควบคุมเข้มขึ้นควรเพิ่ม geofence, การผูกอุปกรณ์ หรือ Bluetooth beacon

## ข้อมูลใบหน้าและความเป็นส่วนตัว

- ใช้ `@vladmandic/human` และโมเดลที่เสิร์ฟจาก `/models/human` ของระบบเอง ไม่มี API คิดค่าบริการต่อครั้ง
- การประมวลผลภาพเกิดในเบราว์เซอร์ ระบบไม่อัปโหลดหรือเก็บรูป/วิดีโอใบหน้าต้นฉบับ
- เก็บ Face Embedding 3 ตัวอย่างแบบ AES-GCM โดยสืบคีย์จาก `APP_SECRET` และผูก ciphertext กับรหัสพนักงาน
- ตาราง Face Profile เปิด RLS และปิดสิทธิ์ `anon`/`authenticated`; ข้อมูลออกจากเซิร์ฟเวอร์ไม่ได้
- การลงทะเบียนต้องทำโดยผู้ดูแลหรือผู้จัดการ พร้อมยืนยันความยินยอม และสามารถลบหรือลงทะเบียนใหม่ได้
- Audit log เก็บผู้ลงทะเบียน/ลบ คะแนนตรวจ และเวลา แต่ไม่เก็บ Face Embedding

Anti-spoof/Liveness แบบ Open Source บนเบราว์เซอร์ช่วยป้องกันรูปถ่ายและวิดีโอทั่วไป แต่ไม่ใช่การยืนยันตัวตนระดับธนาคาร รายการผิดปกติหรือข้อพิพาทควรมีขั้นตอนตรวจสอบโดยผู้จัดการร่วมด้วย
