# ระบบลงเวลาเข้า–ออกงานพนักงาน

เฟสแรกของระบบลงเวลารองรับการสแกน QR จากสมาร์ทโฟน เชื่อมรายการลงเวลาเข้ากับกะที่จัดไว้ให้อัตโนมัติ และแสดงสถานะพนักงานของสาขาแก่ผู้ดูแล

## การติดตั้ง

1. ตั้งค่า `APP_SECRET` ฝั่งเซิร์ฟเวอร์ให้เป็นค่าสุ่มยาวอย่างน้อย 32 ตัวอักษร ห้ามใช้ตัวแปรที่ขึ้นต้นด้วย `VITE_`
2. ติดตั้ง migration ตามสภาพแวดล้อม
   - PostgreSQL ปกติ: `npm run db:migrate`
   - Supabase: deploy ไฟล์ `supabase/migrations/20260921054852_employee_attendance_qr.sql` ตามกระบวนการ migration ของโครงการ
3. เปิด `/attendance` สำหรับพนักงาน หรือเลือกเมนู **ลงเวลาเข้า–ออกงาน**
4. ผู้ดูแลระบบหรือผู้จัดการเปิด `/attendance/kiosk` บนจอประจำสาขาเพื่อแสดง QR

## ขั้นตอนใช้งาน

1. พนักงานเข้าสู่ระบบบนสมาร์ทโฟนและเปิดหน้าลงเวลา
2. สแกน QR จากจอสาขาด้วยกล้องในหน้าเว็บ หรือกล้องปกติของโทรศัพท์
3. ระบบแสดงว่าจะเป็นการ **เข้างาน** หรือ **ออกงาน** ให้พนักงานยืนยันก่อนบันทึก
4. เมื่อเข้างาน ระบบค้นหากะของพนักงานในช่วง 2 ชั่วโมงก่อนเริ่มกะถึง 4 ชั่วโมงหลังสิ้นสุดกะ แล้วผูกกะและคำนวณเวลาสายให้อัตโนมัติ
5. เมื่อออกงาน ระบบคำนวณเวลาทำงาน เวลากลับก่อน และเปลี่ยนสถานะกะเป็นเสร็จสิ้น

หากไม่พบกะที่ตรงกัน ระบบยังบันทึกเวลาได้ แต่กำหนดสถานะเป็น `pending` เพื่อให้ผู้ดูแลตรวจสอบภายหลัง

## การป้องกันการบันทึกซ้ำและการส่งต่อ QR

- QR ลงนามด้วย HMAC และหมดอายุภายใน 45 วินาที จอ kiosk สร้าง QR ใหม่ทุก 30 วินาที
- QR ใช้ได้เฉพาะพนักงานของสาขาที่สร้าง QR นั้น
- คำขอเดิมส่งซ้ำได้อย่างปลอดภัยด้วย idempotency key
- พนักงานหนึ่งคนมีรายการเข้างานที่ยังไม่ปิดได้เพียงรายการเดียว
- ตารางลงเวลาไม่เปิดให้ `anon` หรือ `authenticated` อ่านหรือเขียนตรงจาก Data API การใช้งานทั้งหมดต้องผ่าน API ของแอป

QR แบบหมุนช่วยลดความเสี่ยงจากภาพเก่า แต่ยังไม่สามารถยืนยันตำแหน่งทางกายภาพได้ทั้งหมด หากต้องการการควบคุมเข้มขึ้นควรเพิ่ม geofence, การผูกอุปกรณ์ หรือ Bluetooth beacon

## ขอบเขตสแกนใบหน้า

โครงสร้างข้อมูลรองรับวิธี `face` แล้ว แต่เฟสนี้ยังไม่เปิดรับรูปใบหน้าหรือทำ face matching เพราะระบบจริงต้องมี liveness detection, ขั้นตอนลงทะเบียนใบหน้า, เกณฑ์ความมั่นใจ, การเข้ารหัส biometric template, อายุการเก็บข้อมูล และขั้นตอนยินยอม/ลบข้อมูลที่ชัดเจนก่อนนำไปใช้

เมื่อเลือกผู้ให้บริการที่รองรับ liveness แล้ว สามารถเพิ่ม adapter ฝั่งเซิร์ฟเวอร์ให้สร้าง attendance session ผ่าน transaction เดียวกับ QR ได้ โดยไม่ต้องเปลี่ยนโครงสร้างรายงานเวลา
